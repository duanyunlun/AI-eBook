# AI-eBook 架构设计

状态：首版架构定稿  
日期：2026-09-02

当前实现已覆盖 PDF、TXT 与 Markdown 书库、页/章阅读位置、章节目录、文字/区域证据、流式伴读、记录与整本思考总结、FTS5 检索、Markdown 归档和本地 Git 历史。EPUB、向量检索、OCR、区间总结和 DSH sidecar 属于后续里程碑。

## 1. 产品定位

AI-eBook 不是在传统阅读器旁边附加聊天窗口，而是以阅读器作为采集入口的个人知识库。书籍文件可以删除或替换，用户留下的引用、截图、理解、AI 回答、章节总结和阅读经历必须继续存在并可追溯。

首版只服务桌面端个人使用场景：

- 打开书籍后恢复到上次阅读位置。
- PDF 使用内置书签作为章节目录；TXT 与 Markdown 按常见标题格式生成可跳转目录。
- 阅读区底部的滑杆、加减按钮以及触摸板或触屏的双指手势均可调整页面缩放比例。
- 使用可配置快捷键进入思考模式，通过键盘输入问题或理解。
- 使用鼠标选择文字、图片或页面区域作为批注来源。
- AI 在侧边栏回答，只有用户确认的内容才进入知识库。
- 对当前书籍中已确认的个人思考生成整本总结。
- 从个人知识库检索与当前内容相关的既有知识。
- 使用 Git 保存知识内容的修改历史。

### 1.1 首版不做

- 手写、笔迹识别、OCR 和电子笔适配。
- Android、iOS 和触屏交互。
- 多设备实时同步及自动冲突合并。
- 独立图数据库、自动知识推理、内置向量数据库和常驻本地模型服务。
- DRM 电子书解密。
- 一次性兼容所有电子书格式和所有 AI 厂商协议。

移动端后续只要求兼容知识库数据格式；不为尚未开始的移动端提前抽象桌面 UI。

## 2. 技术选择

| 范围 | 选择 | 用途 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | macOS 首先验证，保留 Windows/Linux 构建能力 |
| 前端 | TypeScript、原生 Web Components、CSS | 书架、阅读区、选择工具和 AI 侧栏 |
| 本地核心 | Rust | 文件、数据库、Git、网络请求和安全边界 |
| 流式电子书 | foliate-js | 首先支持 EPUB，之后增加 MOBI/AZW3/FB2/CBZ |
| PDF | PDF.js | 连续滚动、按需渲染、文本选择和区域截图 |
| 纯文本 | 浏览器原生文本渲染 | TXT、Markdown 章节识别、连续阅读和文本选择 |
| 状态与检索 | SQLite、FTS5 | 阅读状态、临时草稿和知识全文索引 |
| 知识关系 | SQLite 邻接表、递归 CTE | 来源追踪、跨书关系和局部知识图 |
| 历史 | libgit2（Rust `git2`） | 在用户知识库目录内创建提交 |
| AI | Rust HTTP、SSE | OpenAI Chat/Responses、Anthropic Messages、Gemini GenerateContent |
| 密钥 | 系统钥匙串 | API Key 不进入配置、日志或 Git |

首版不引入前端状态框架。阅读器只有少量全局状态，原生模块和事件足够；当实际 UI 复杂度证明这一选择不足时再引入框架。

### 3.1 模块边界

- 前端负责渲染、用户选择、快捷键和可见交互状态。
- Rust 负责持久化、文件读取、Git、AI 网络请求和密钥访问。
- 前端只通过书籍 ID、章节 ID 和资源 ID 请求数据，不把任意文件路径交给读取命令。
- AI 回答首先作为 SQLite 会话消息保存；确认保存后才晋升为知识项并写入 Markdown 和 Git。
- SQLite 是运行时状态和可重建索引，不是知识内容的唯一来源。

## 4. 运行时数据目录

源码、运行状态和个人知识必须分开。

### 4.1 应用数据

应用数据使用操作系统提供的应用数据目录：

```text
<app-data>/
├── state.sqlite              # 阅读位置、书籍版本、会话消息和 FTS5 索引
├── library/                  # 导入后由应用管理的原始书籍
└── cache/                    # 封面、分页和可删除的解析缓存
```

原始书籍不进入 Git。删除书籍时删除 `library/` 中对应资源和可重建缓存，不删除知识库内容。

### 4.2 个人知识库

知识库由用户选择位置，使用开放格式：

```text
<vault>/
├── .git/
├── books/<book-id>/
│   └── book.md               # 永久书籍对象与元数据
├── items/
│   └── <item-id>.md          # 已确认的思考、概念、结论和总结
└── assets/
    └── <sha256>.webp         # 截图等内容寻址附件
```

`Book` 是永久知识对象，`Edition` 是可删除的书籍文件。二者不得合并：

- `Book` 使用应用生成的永久 UUID。
- `Edition` 使用文件 SHA-256 标识，并在 SQLite 中指向 `Book`。
- 相同哈希重新导入时自动绑定。
- ISBN 等元数据一致但哈希不同时，提示用户是否作为新版绑定。
- 只有书名相似时不自动绑定。
- 用户可在书库中修改 `Book.title`；该操作不重命名原始文件，但会同步更新 SQLite、书籍 Markdown 和知识库 Git 历史。

知识库本身就是 RAG 可摄取的语料。需要对接外部工具时，从 Markdown 生成带 `book_id`、`chapter_id`、`category`、`locator`、`type`、`creator`、`basis`、`review_state`、`evidence`、`links` 和 `content_hash` 的 JSONL；JSONL 是可重建导出物，不提交为源数据。

## 5. 知识图谱契约

知识库使用“证据、知识项、关系、会话”四类核心对象：

| 对象 | 职责 |
| --- | --- |
| `Evidence` | 保存文字选区、截图、书籍定位和外部引用的不可变快照 |
| `KnowledgeItem` | 保存思考、问题、答案、概念、结论和总结 |
| `KnowledgeEdge` | 保存知识项之间可追溯的语义关系 |
| `Thread`、`Message` | 保存思考模式和记录模式产生的原始对话 |

`KnowledgeItem.category` 是用户可修改的单层自定义分类；`book_id` 是独立的书籍归属，两者可以同时存在。完整知识库页面按书籍或自定义分类筛选，并允许用户直接新增、修改和删除知识项。删除会清理运行时记录和开放 Markdown 文件，但内容仍可从知识库 Git 历史恢复。

首版关系类型固定为 `quotes`、`asks_about`、`derived_from`、`summarizes`、`supports`、`contradicts`、`related_to` 和 `mentioned_in`。增加关系类型必须通过 schema 迁移，不能由模型生成任意字符串。

### 5.1 来源与审核

知识项使用三个互不替代的维度描述来源：

- `creator`：正文由 `user` 或 `ai` 生成。
- `basis`：内容依据来自 `user_thought`、`book`、`external` 或 `mixed`。
- `review_state`：内容处于 `draft`、`confirmed` 或 `rejected`。

用户亲自输入的记录保存后即为 `confirmed`。AI 回答在确认前只是 SQLite 会话消息；用户确认录入后直接创建 `confirmed` 知识项并写入 Markdown 和 Git。`draft` 与 `rejected` 状态保留给后续可编辑草稿流程。AI 对用户思考的总结记录为 `creator: ai`、`basis: user_thought`，并通过 `summarizes` 关系指向原始思考。

原始对话不是知识图谱节点。对话只保存在会话日志中，确认后的答案或总结才晋升为 `KnowledgeItem`，防止知识图谱被每个对话片段填满。

### 5.2 检索与关联图

伴读检索按以下顺序组合结果：

1. 当前书籍、章节和选区的精确关联。
2. SQLite FTS5 全文匹配。
3. 可选的向量语义匹配。
4. 对命中知识项扩展一至两跳已确认关系。
5. 按相关度、用户确认状态、来源和时间重新排序。

侧栏展示的关联图必须来自本次实际送入模型的知识项，不能展示一套关系却让模型使用另一套隐藏上下文。首版只渲染以当前选区或问题为中心的局部子图。

完整知识库的中间区域采用无背景网格、可拖拽并以指针为中心缩放的 SVG 画板。拖动画板时阻止 WebView 原生选区，不能出现整页选择高亮。知识项以紧凑圆形节点呈现，圆心只显示由问题或标题提取的一至两个字，完整内容仅在点击后进入右侧抽屉；用户可右键节点选择本机持久保存的填充色。`KnowledgeEdge` 是带方向和关系名称的连线；节点和连线均可点击。画板不绘制分组外框，也不显示书名；书籍只作为内部布局和左侧筛选条件，自定义分类可保留轻量标题。用户可用适应内容按钮返回全局总览。

当前版本渲染接口返回的局部结果集。知识量超过单个局部子图承载范围后，服务端必须先返回分类、书籍及数量等聚合节点；用户展开某一分组时再按需加载该组的有限节点和一至两跳关系，不允许把完整知识库一次性载入前端。搜索结果也作为独立局部子图渲染，由分类抽屉负责快速缩小范围。

SQLite 邻接表是首版图关系的唯一运行时存储，不引入 Neo4j。向量索引和 FTS5 都是可重建派生数据，不是知识内容的唯一来源。

## 6. 知识文件契约

每个 Markdown 文件使用 YAML Front Matter 保存稳定元数据。首版 schema 为 `1`，未来不兼容变更必须通过显式迁移完成。

```markdown
---
schema: 1
id: "018f..."
book_id: "018e..."
chapter_id: "chapter-07"
category: "方法论"
type: "note"
creator: "user"
basis: "book"
review_state: "confirmed"
created_at: "2026-08-31T10:00:00+08:00"
evidence:
  - id: "0190..."
    edition_hash: "sha256:..."
    locator: "epubcfi(...)"
    progression: 0.314
links:
  - type: "related_to"
    target: "0191..."
ai:
  provider: "openai-compatible"
  model: "model-name"
---

# 批注标题

> 被引用的原文快照。

用户自己的理解。

## 已确认的 AI 回答

只有用户确认录入的回答出现在这里。
```

AI 字段只记录复现和辨识所需信息，不保存 API Key、完整请求头或模型内部推理内容。纯用户批注省略 `ai`。

Markdown 是已确认知识的开放归档格式，必须包含足以重建来源和关系的数据。SQLite 负责运行时查询和未确认会话；两者不一致时，已确认知识以 Markdown 为准并重建索引。

## 7. 定位与恢复

当前版本在阅读位置稳定后防抖写入 SQLite，并在切换书籍和正常退出时立即落盘。PDF 保存页码，TXT 与 Markdown 保存章节序号。

以下是 EPUB 接入后需要实现的目标定位契约：

定位采用多级回退，不能只保存页码：

| 格式 | 主定位 | 回退信息 |
| --- | --- | --- |
| EPUB | 章节 href、EPUB CFI | 原文摘录、章节进度、全书进度 |
| PDF | 页码、归一化矩形 | 原文摘录、页内进度 |
| TXT | 字符偏移 | 前后文、全书进度 |

恢复顺序是精确定位、原文匹配、章节进度、全书进度。版本变化导致定位降级时提示用户，不静默跳到可能错误的位置。

## 8. 阅读与 AI 交互

阅读界面首次启动跟随系统明暗外观；用户手动切换后保存本地偏好，PDF 页面保持原始配色。

主菜单和批注侧栏默认收起，不显示独立按钮。鼠标在左右 `32px` 边缘停留约 150ms 后直接展开对应抽屉，离开抽屉约 300ms 后自动收起；右侧输入聚焦、AI 回答中或存在未保存内容时保持展开。点击阅读区或按 `Esc` 立即收起。批注栏可拖动左边缘或用方向键调整宽度，默认下限 240px、硬上限为当前窗口宽度的 50%，并保存用户选择；窄窗口优先服从 50% 上限。拖动边缘时扩大命中区域并禁用、清除 PDF 原生文字选区，避免调整宽度误选正文。页码和缩放滑动条默认隐藏，鼠标进入阅读区底部或键盘聚焦控件时显示；触屏边缘滑入手势留到移动端实现。

知识库页面沿用相同交互：分类与条目列表组成左侧抽屉，知识详情组成右侧抽屉，两者默认收起并由页面左右 `32px` 边缘触发。知识详情默认以经过安全清理的 Markdown 阅读态展示，用户点击编辑后才切换到表单；编辑表单固定在抽屉内，正文占用剩余高度并在内部滚动，不允许拖拽改变尺寸或挤压底部操作栏，空状态提示不占用布局空间。新建入口位于左侧抽屉，左侧右键菜单只提供新建和删除；书籍、自定义分类等一级分组使用明确分隔线。删除采用应用内两次点击确认，不依赖 WebView 系统对话框。点击知识条目或图谱节点直接展开详情，点击中间图谱收起两侧。右栏宽度独立记忆，下限 280px，上限为窗口宽度的 50%。应用内滚动区域保留滚轮、触控板和键盘滚动能力，但不持续显示滚动条。

### 8.1 思考模式

```text
正常阅读
  -> 用户选择文字/区域（可选）
  -> 快捷键进入思考模式
  -> 输入问题或理解
  -> 停止输入后发起 AI 请求
  -> 侧栏流式显示回答
  -> 展示回答及本次使用的关联知识子图
  -> 用户继续追问、确认录入或丢弃
```

- 快捷键可配置，只在阅读窗口内生效，不注册系统级监听。
- 选择文字或完成区域截图只更新待处理上下文，不自动展开侧栏。用户在阅读正文内取消选择时同步清除文字选区，也可通过选区卡片右侧按钮手动清除。用户通过快捷键或选区右键菜单明确选择“思考”或“记录”后才展开对应模式。
- 自动捕捉只在用户主动进入思考模式后开始。
- 新输入使未完成请求失效，避免旧回答覆盖新思考。
- 输入框内部只保留右上角高度拖拽手柄；拖拽采用窗口级指针生命周期并在期间禁用原生选区，即使指针移出窗口也不能误选正文或界面文字。`Enter` 发送并在回复期间排队，`Ctrl/Command+Enter` 中断当前回复并插队，`Shift+Enter` 换行；界面不显示独立发送按钮、策略下拉框或可见状态行。回答可归档时，在右侧栏左侧框线外靠近底部的位置悬浮显示主题色圆形羽毛笔按钮，用于录入知识库；按钮不占用侧栏内部布局，并随侧栏一起展开、收起和移动。
- 用户可随时清空当前思考对话；清空会关闭活动会话并重置侧栏上下文，已确认归档的知识及其 Git 历史不受影响。
- 默认上下文包含当前作品名称、格式、总页数、当前页内容、当前选择和本次检索命中的关联知识。文字 PDF 按需提取当前页正文；扫描页按需发送压缩后的当前页图像；用户选区仍作为独立上下文，不与整页内容混合。
- 伴读系统提示词可在设置中修改，固定的资料不可信、来源区分和信息边界规则始终追加，不能被自定义提示词关闭。
- 书籍正文始终视为不可信数据，不能借由提示词触发文件、Git 或系统操作。
- 未确认回答只保存在 SQLite 会话中，不进入 Markdown 和 Git。

### 8.2 记录模式

```text
正常阅读
  -> 用户打开批注侧栏
  -> 以块状编辑体验记录个人思考
  -> 原文立即保存为用户知识项
  -> 用户确认保存记录
  -> 手动触发总结时归纳本书已确认的个人思考
```

“类似 Notion”只约束编辑体验，不复制其完整块数据模型。首版正文保存为普通 Markdown；出现跨段引用和独立块关系的真实需求后，再增加稳定块 ID。

记录正文输入框填满记录面板剩余高度，不提供浏览器原生拖拽缩放锚点；输入 `/` 可搜索并插入正文、标题、列表、待办、引用和分割线等 Markdown 内容类型。操作按钮紧随输入框并位于侧栏底部，空状态栏不保留高度。操作行左侧提供“当前书籍记录”，直接打开知识库并筛选当前书籍；总结与保存命令保持在右侧，避免在记录模式内维护第二套知识列表。

### 8.3 引用与截图

- 文本选择保存原文快照和定位，之后即使原书被删除仍可阅读。
- PDF 页面区域保存为裁剪后的 WebP；EPUB 图片留待 EPUB 阅读器接入后实现。
- 附件以内容哈希命名，相同内容只保存一次。
- 截图进入 AI 上下文需要模型支持图像；文本模型只能保存附件，不能假装理解图片。
- 文字选区和区域截图共用“思考、记录、翻译、解释”右键菜单。翻译目标语言由设置页选择；内容完全属于目标语言时转为解释，中英等混杂内容仍执行翻译。
- 除输入框等需要保留系统编辑菜单的控件外，软件内所有可选择文字和图片共用上述右键菜单。只有阅读正文选区和 PDF 阅读区截图可绑定当前书籍；从侧栏、书库、知识库、设置或弹窗等非正文区域产生的知识强制取消书籍关联，标记为外部依据并写入“默认分类”。
- 翻译和解释使用较高的独立模态窗口，上方保留可滚动的原始文字或截图，下方以经过安全清理的 Markdown 流式显示结果。生成状态以强调色显示在结果标题右侧，完成或失败后保留最终状态。点击外部遮罩或按 `Esc` 不关闭，只能点击窗口关闭按钮。联网核验仅在当前 AI 服务本身提供联网能力时使用，不能虚假标记为联网结果。

### 8.4 整本思考总结

当前版本汇总当前书籍中已确认的用户记录，限制单次送入模型的文本长度，并生成一个新的总结知识项。总结通过 `summarizes` 关系连接本次实际送入模型的原始知识项；重新总结不会覆盖用户记录或旧总结。按 Locator 选择连续区间、跨章节拆分及逐章总结属于后续里程碑。

## 9. AI 与 Agent 边界

AI 适配层使用统一的文本/图片消息模型，由 Rust 分别映射到以下流式协议：

- OpenAI Chat Completions；同时作为 OpenAI-compatible 入口，覆盖 Ollama、LM Studio、vLLM、DeepSeek、OpenRouter 等兼容服务。
- OpenAI Responses。
- Anthropic Messages。
- Gemini GenerateContent。

用户可配置协议、`base_url`、模型和伴读系统提示词。非敏感配置保存在本地应用设置，API Key 按服务地址隔离并只保存在系统凭据库；macOS 使用 Keychain Services，Windows 使用 Credential Manager，Linux 使用 Secret Service。远程服务地址必须使用 HTTPS，回环地址可使用 HTTP，也允许本地兼容服务不配置 API Key。

内部只保留当前需要的数据：

```text
generate(messages, model, options) -> stream events
cancel(request_id)
```

不创建运行时插件系统，也不复制 Agent 软件的完整 provider 运行时。Azure、Bedrock、Vertex AI、OAuth 订阅登录等专用鉴权不属于上述四种 wire protocol，出现真实需求后独立增加。

### 9.1 DSH 集成边界

当前版本只管理 DSH 运行时的检测、安装与更新，伴读仍直接使用内置 AI 适配层。后续可将 DSH 作为可选 sidecar，通过 SDK JSON-RPC 与 Rust 核心通信；知识库 schema、Markdown 契约和 Git 历史不得依赖 DSH 的内部会话格式。

设置作为主菜单右侧滑出的二级抽屉呈现，打开时保留一级菜单，点击阅读区、打开另一侧抽屉或按 `Esc` 时随一级菜单收起。内容按“外观、AI、快捷键、数据”排列，避免长表单混杂不同职责；DSH 运行时属于 AI 页，个人知识库存储位置属于数据页。快捷键按“导航、阅读动作、AI 对话”分组，支持点击录入、冲突提示、单项清除和恢复默认，也允许 `A` 等单按键绑定。快捷键只在应用窗口内生效，任何文本输入、下拉框或可编辑区域聚焦时，单按键导航和阅读动作自动停用；问题输入框仅额外响应发送与插队命令。

外观只维护浅色与深色各自的一种主题色，当前主题即时使用对应颜色；UI 字体在首次打开外观页时由原生端扫描 macOS、Windows 或 Linux 的系统字体目录并返回字体家族，另保留“系统默认”，字体扫描不进入冷启动路径。字号在 12–18px 间调整，通过统一比例缩放原有文字层级，不改变 PDF 原文渲染。外观和快捷键均保存在本机应用设置中并即时生效；目录可从左侧菜单、阅读区顶部悬浮按钮或可配置快捷键打开。

设置页可随时检查、安装或更新由 AI-eBook 管理的 DSH 运行时，也可修改并持久化 npm 源地址，默认使用国内 npmmirror。界面先显示当前版本，用户主动检查后才联网查询最新版，发现差异后再开放更新操作；检查和安装期间显示动态进度条与已用时间，不伪造 npm 无法提供的完成百分比。托管运行时及其独立 npm 缓存位于应用数据目录并优先于系统全局安装，npm 子进程忽略应用进程继承的代理配置，不依赖或修改全局 npm 缓存和 root 所有的全局目录，也不进入阅读器冷启动路径。

伴读输入框下方使用固定三列单行状态栏：左侧只显示排队和知识库写入等非回答操作状态，中间显示录入知识库操作，右侧固定显示排队或插队策略选择。AI 思考、回答、完成或失败状态以强调色附在当前 AI 消息标题后并保留；失败状态使用错误色。记录模式只保留共用状态信息。用户消息使用强调色边线和浅色背景，与 AI 回复保持明确区分。

自定义 `reader` profile 只允许调用受限阅读工具：`get_book_context`、`search_knowledge`、`get_related_graph`、`create_note_draft`、`propose_concepts`、`propose_relations` 和 `summarize_thoughts`。不得加载 Shell、文件编辑器或不受限文件系统工具。

直接 AI 适配层继续负责当前伴读请求。后续接入 DSH 时只在首次进入伴读对话后按需启动，并保留直接 AI 适配层作为后备，不能增加阅读器冷启动路径。

## 10. Git 策略

Git 只管理 `<vault>`，不管理书籍、数据库、缓存和密钥。

自动提交时机：

- 用户确认保存或修改批注。
- 用户确认保存章节总结。
- 用户删除知识条目。

不在翻页和普通阅读位置更新时提交。一次用户动作引起的知识文件与附件变化应放进同一提交，提交信息使用中文，例如 `记录《书名》第七章批注`。

本地 Git 只提供历史回溯，不能防止磁盘或设备损坏。远程私有仓库同步属于后续独立功能；实现前不得宣传为已经防丢。

## 11. 性能与安全约束

- 启动阶段只打开状态数据库并恢复必要窗口状态，不扫描书库、不重建全文索引、不执行 Git 操作。
- 书籍解析、全文索引、封面生成和总结在后台执行。
- 大文件按范围读取，不把完整文件通过 Tauri IPC 复制到前端。
- PDF 使用 Worker，只保留当前页附近的渲染结果。
- PDF 页面渲染内部链接注释层，目录和章节链接通过 PDF 目标引用跳转到连续滚动页面。
- 后续 EPUB 接入必须限制解压条目数量、单条目大小和总展开大小，并拒绝目录穿越路径。
- 后续 EPUB 接入必须默认禁用脚本，并隔离渲染内容与应用权限。
- AI 只接收用户当前动作需要的内容；发送前在侧栏展示上下文范围。
- API Key 只存系统钥匙串，错误和调试日志必须脱敏。

以下数字是验收目标，不是当前已验证事实：

- 开发机冷启动到可操作阅读界面不超过 1.5 秒。
- 恢复已导入 EPUB 的当前章节不等待全文索引。
- 打开超大书籍时内存占用不随文件总大小线性增长。

目标必须在真实样本和发布构建上测量；未测试前不得报告为已达成。
